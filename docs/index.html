    ❔ How X-Ray works
    
    
    
      
    Not a guess. The recipe.
    
      
      
        
    1. Website: fetches the page through free CORS readers (AllOrigins → CodeTabs → Jina Reader), gets a rendered snapshot, screenshot and Wappalyzer tech list from Microlink’s free tier (or a thum.io screenshot), then downloads the main JS bundles and stylesheets.
      2. 
        
    2. Reads the code: about 110 fingerprints for frameworks, 3D/animation libraries, analytics, payments and build tools; versions where the code shows them; endpoint, route, source-map, storage-key and AI-prompt candidates.
      3. 
        
    3. Design system: color frequency, CSS variables, fonts, type and spacing scales, radii, breakpoints, keyframes, and the screenshot palette.
      4. 
        
    4. Apps: APK (manifest strings, permissions, dex packages, Flutter / React Native / Capacitor / Unity / Xamarin detection), IPA and zipped macOS .app (Info.plist, Mach-O type, linked frameworks, extensions), ASAR, JAR, browser extensions, single files.
      5. 
        
    5. Screenshots: measured palette plus an AI vision teardown.
      6. 
        
    6. AI (optional, your free key): writes the teardown in REA-style sections, a rebuild plan, an original clone (tested in a hidden sandbox before launch) and a prompt pack.
      7. 
      
    
      
    No hacking. Learning only.
    
      
    X-Ray reads only what a site already sends to any browser, or files you own. Use it for learning, interoperability and inspiration. Rebuilds must be original: don’t copy names, logos, trademarks, text, images or other copyrighted assets, and respect each site’s terms and each app’s license.
